Sheet GA-1 · general arrangement

One engine. Everything else is a client.

The engine serves HTTP and WebSocket on localhost, and that is the only surface it has. Pages, terminals and desktop shells are all clients of the same bus. Policy arrives signed from upstream and is enforced on your machine.

Sheet GA-2 · detail · what the frame carries

The frame, in code.

Six decisions the framework makes so a harness does not have to. Every snippet runs against the real crates and the real config surface.

A1 · the bridge

The frontend is detached.

The framework ships connectors, never UI. A page imports client.mjs, a zero-dependency module the engine itself serves, and speaks HTTP and WebSocket to localhost. The same session surface answers a browser page, a terminal, and a desktop window, so the frontend can live on the web or on your own infrastructure. Conveniences for Vue, React and Svelte ride separately, one milestone each.

// the Rust client, galvena_bridge::client, answers the same surface for terminal and native shells

// any page, any host: the engine serves the module itself
import { createClient } from "/bridge/client.mjs";

const bridge = createClient("http://127.0.0.1:8317");

const ws = await bridge.defaultWorkspace();
const s  = await bridge.createSession(ws, "first light");

const off = await bridge.subscribe(s.id, {}, (frame) => {
  if (frame.type === "turn") render(frame.turn);
});

A2 · the binary

One binary, three ways in.

Invoked at a TTY it is the CLI. galvena serve makes it a headless engine, and the desktop shell is just another client that opens once an engine answers.

$ galvena serve
# the engine, on 127.0.0.1:8317
$ galvena chat <id> "hello"
# the stub replies. no key needed

A3 · the policy

Signed upstream. Enforced locally.

Rules ride down the subscription chain and apply on your machine. The ask-on-modify guardrail stands in front of every mutating tool call, and a policy file can allow, deny, or escalate at the bus seam.

ask = true             # before every mutating tool call
policy = "./policy.toml" # allow · deny · escalate

A4 · the tool seam

Tools load. Then they wait.

MCP servers mount only behind an explicit --mcp, because connecting runs their code. Every mounted tool loads disabled, and a flip persists across restarts.

$ galvena serve --mcp --enable-tool fetch

A5 · the tree

Sessions are an event tree.

Profile → Project → Workspace → Session → Turn, journaled on disk beside the binary. Secrets live in the OS keychain vault, and the database path is asked for, never invented.

export GALVENA_DB=./galvena.db
# or db = "./galvena.db" in harness.toml

A6 · the providers

Any model. Or none.

The stub provider answers offline on first run: no key, no network, no telemetry. A real model is one line of harness.toml away, pointed at a cloud or at your own box. Anthropic, OpenAI and Responses drivers cover their compatible servers, so local stacks ride the same seam.

# "stub", the default, answers offline: no key, no network
provider = "openai"        # or "anthropic"
base_url = "http://127.0.0.1:11434"
                             # Ollama · vLLM · LM Studio · OpenRouter

Sheet GA-3 · detail · the entry point

Start from a harness that already answers.

The starter, galvena/galvena, rides the framework as versioned dependencies. Clone it and build it: a functioning harness answers. No account, no cloud, no telemetry; nothing is required, everything is yours.

Terminal · first runPOSIX shell
$ git clone https://github.com/galvena/galvena
$ cd galvena
$ ./galvena link         # once, ever
$ galvena init           # store, tree, vault, skills
$ galvena ui setup && galvena ui build  # the frontend, once
$ galvena serve          # the engine on localhost:8317
/ · the harness frontend /app · the sample client galvena tui · the same session surface
Yours, from the first commit

  • the frontend: Nuxt on the bridge client
  • the shells: sample page, TUI, desktop host
  • the skills: .ai/skills, seeded and updated
  • harness.toml: flag over file over default
Rides in, versioned

  • the compatibility trinity
  • the store and the vault

Fixes land upstream. You never fork the frame.
